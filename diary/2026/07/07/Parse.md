PostgreSQL 使用一套基于消息的前端/后端协议。在这套协议中，**扩展查询**（Extended Query）将 SQL 执行拆分成多个步骤：Parse（解析）、Bind（绑定）、Describe（描述）、Execute（执行）和 Sync（同步）。其中 **Parse 消息**负责把一条带有参数占位符的 SQL 文本转换成一个服务器端的**预备语句**（prepared statement），为后续绑定参数并高效执行做准备。

下面从消息结构、字段含义、服务器响应、完整流程以及具体示例几个方面，对 Parse 协议做一次深入详解。

---

# 1. Parse 消息在协议中的位置

PostgreSQL 的消息流中，所有消息都由 **1 字节的消息类型标识 + 4 字节长度（包括长度自身） + 消息体** 构成。Parse 消息的类型标识为 `'P'`（ASCII 80）。

一次典型的扩展查询流程如下：

```text
Parse  →  Bind  →  Describe(可选)  →  Execute  →  Sync
```

- **Parse** 定义 SQL 模板（含 `$1`, `$2`, ... 占位符）并生成预备语句，此时不执行。

- **Bind** 将实际的参数值绑定到占位符，生成一个**门面**（portal）。

- **Execute** 执行门面，返回结果。

- **Sync** 结束当前事务，并使服务器回到就绪状态。

---

# 2. Parse 消息格式详解

## 2.1 逻辑结构

字段	类型	说明
消息类型	Byte1 (`'P'`)	标识这是一个 Parse 消息
消息长度	Int32	自描述长度，包括长度字段自身以及后续所有字段，**不包括类型字节**
语句名	String (以 `\0` 结尾)	预备语句的名称，空字符串表示未命名语句
查询字符串	String (以 `\0` 结尾)	需要预编译的 SQL 文本，可以包含 `$n` 占位符，**只能包含一条 SQL 语句**（不能有分号分隔的多条）
参数数据类型个数	Int16	后面紧跟的 OID 数量，可以为 0
参数数据类型 OID	Int32 数组	每个参数期望的数据类型 OID（如 `23` 代表 `int4`），`0` **表示未指定，由服务器推断**。数组长度由前面的 Int16 决定

## 2.2 字节级表示（伪结构体）

```text
+------+-----------+------------------+-------------------+---------------------+--------------------------+
| 'P'  |  长度 N   |  语句名 + '\0'   | 查询字符串 + '\0'  |  参数个数 (Int16)    |  OID1, OID2, ... (Int32) |
+------+-----------+------------------+-------------------+---------------------+--------------------------+
```

- **长度 N** 的计算（大端序）：

  `N = 4 + 语句名字节数(含结尾0) + 查询字节数(含结尾0) + 2 + (参数个数 × 4)`

- **语句名**和**查询字符串**都以 C 风格的 `'\0'` 结尾。

- **参数个数**可以大于或小于实际 SQL 中 `$n` 的最大编号：

  + 如果指定个数 > 实际占位符数，多余 OID 会被忽略。

  + 如果指定个数 < 实际占位符数，未指定类型的参数将被标记为 “待推断”。

  通常习惯写 `0`（全部推断）或 **与 `$n` 数量一致**。

---

# 3. 服务器响应

服务器收到 Parse 消息后，会进行语法分析、语义分析并生成查询计划，然后把预备语句存储起来（以语句名为键）。然后回复以下消息之一：

- **ParseComplete**

  类型标识 `'1'`
  长度 `4`（只包含长度字段自身，无附加数据）
  字节序列：`0x31 0x00 0x00 0x00 0x04`

- **ErrorResponse**

  类型标识 `'E'`
  包含错误码、错误信息等字段，以 `'\0'` 结尾。若解析失败（如语法错误、表不存在）将返回此消息。

---

# 4. 参数类型推断规则

- 如果在 `Parse` 消息中为参数指定了非零的 OID（例如 `23` 代表 `INTEGER`），服务器就会按照该类型生成计划。后续 `Bind` 时参数值类型必须兼容（可以隐式转换）。

- 如果 OID 为 `0` 或未被指定（参数个数 < 参数最大位置），服务器会在第一次 `Bind` 时根据实际传入的参数值自动推断类型，并重新计划。这可能导致同一语句在推断前后计划不同，对性能有一定影响。

- 建议：对于性能关键的语句，明确指定参数类型。

常见类型 OID 示例：

类型	OID
INT4	23
INT8	20
TEXT	25
FLOAT8	701
BOOL	16

---

# 5. 完整交互流程示例

假设客户端想要多次执行 `SELECT $1 + $2`，每次传入不同的整数。

## 5.1 使用未命名语句（空名字）

### (1) `Parse` 消息（创建未命名预备语句）

- 语句名：空字符串 `""`

- 查询：`SELECT $1 + $2`

- 参数个数：`0`（类型全部由服务器推断）

**十六进制消息（逐字节解释）**：

```text
50              -- 'P'
00 00 00 16     -- 长度 = 22（4 + 1 + 15 + 2 + 0）
00              -- 空语句名，只有一个 '\0'
53 45 4C 45 43 54 20 24 31 20 2B 20 24 32 00
                -- "SELECT $1 + $2\0" (15 字节)
00 00           -- 参数个数 0
```

总消息：`50 00 00 00 16 00 53 45 4C 45 43 54 20 24 31 20 2B 20 24 32 00 00 00`

### (2) 服务器 → `ParseComplete`

```tex
31 00 00 00 04
```

### (3) `Bind` 消息（省略详细格式）

- 目标门面可命名为 `""`（未命名门面）或任意名字。

- 参数提供两个 Int4 值（如 10 和 20），可采用文本或二进制格式。

### (4) `Execute` 消息

- 执行门面，返回最大行数。

### (5) `Sync` 消息

- 类型 `'S'`，长度 `4`，确保事务同步。

## 5.2 使用命名语句（"myadd"）

如果想保留预备语句供以后重复使用，可以指定语句名：

- 语句名：`"myadd"`（字符串 `myadd\0`）

- 查询：`SELECT $1 + $2`

- 参数类型明确指定为两个 `INT4`（OID = 23）

构造：

- 语句名：`m y a d d \0` → 6 字节

- 查询：`SELECT $1 + $2\0` → 15 字节

- 参数个数：`2`

- OID 数组：`00 00 00 17 00 00 00 17` （两个 `23`）

长度：4 + 6 + 15 + 2 + 2×4 = 4+6+15+2+8 = 35 → `0x00 0x00 0x00 0x23`
