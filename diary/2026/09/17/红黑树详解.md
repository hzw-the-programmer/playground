# 红黑树 完整详解

## 一、本质

红黑树是**自平衡二叉搜索树 (BST)**。

> 
> 普通 BST 最坏退化成链表 \(O(n)\)；AVL 靠严格高度差约束平衡；**红黑树通过结点着色 + 5 条规则实现近似平衡，保证树高 \(h \le 2\log_2(n+1)\)，查找、插入、删除复杂度都是 \(O(\log n)\)**。

> 
> ⚠️关键点：**它不是严格平衡，是近似平衡。最长路径最多是最短路径的 2 倍。**

### 结点结构

每个结点除 key、left、right、parent 指针，额外保存颜色：

```plaintext
enum Color { Red, Black }
struct Node {
    key: i32,
    color: Color,
    left: *mut Node,
    right: *mut Node,
    parent: *mut Node
}
```

> 
> ✨NIL 哨兵结点：红黑树一般不用`null`，统一用一个全局黑色 NIL 叶子哨兵；所有叶子都是这个 NIL，简化边界判断。

---

## 二、红黑树五大铁律（核心！必须全部满足）

1. 每个结点，颜色只能是红色或者黑色。
2. **根结点一定是黑色。**
3. 所有叶子（NIL 哨兵结点）都是黑色。
4. **红色结点的孩子必须是黑色。不允许红红相连；允许黑黑相连。**
> 
> 翻译：一条路径上不能连续出现两个红色。黑色没有该限制。
5. **黑高性质：从任意一个结点出发，到达它所有后代 NIL 叶子，路径上黑色结点的数量全部相等。这个数目叫该结点的黑高。**

> 
> 👉由 5 条性质可以推导出最长路径 ≤ 2× 最短路径。
> 最短路径：全部都是黑色；最长路径：黑红交替。

> 
> ❗注意：**黑高只统计黑色结点，红色不计入黑高。**

---

## 三、基础操作：左旋 & 右旋

> 
> 插入删除破坏规则之后，修复只靠两类基础动作：**旋转 + 改颜色**。
> 旋转只改动指针，不修改颜色；变色只改颜色不动指针。

- 左旋：以 x 为支点，把 x 的右孩子 y 提升上来，x 变成 y 的左孩子
- 右旋：以 y 为支点，把 y 的左孩子 x 提升上来，y 变成 x 的右孩子

伪代码左旋：

```plaintext
fn left_rotate(x) {
    y = x.right;
    
    x.right = y.left;
    if y.left != NIL { y.left.parent = x; }
    
    y.parent = x.parent;
    if x.parent == NIL { root = y; }
    else if x == x.parent.left { x.parent.left = y; }
    else { x.parent.right = y; }
    
    y.left = x;
    x.parent = y;
}
```

右旋是镜像。

> 
> 💡面试重点：旋转**不会破坏二叉搜索树有序性**！

## 四、插入流程与插入修复

### 插入总步骤

1. 按照普通 BST 规则找到位置插入新结点。
2. **新插入结点默认染成红色！**

> 
> 🤔为什么新结点是红色？
> 如果插黑色：直接破坏黑高性质，祖先所有分支黑高全部错乱，修复代价极大。
> 插入红色：只会有可能违反规则 4（红红相连），不会破坏黑高，只需要处理红红冲突。

> 
> 插入之后只有一种违规可能：**父结点也是红色 → 红红相连**；此时开始循环向上修复。

### 插入修复的三种 case（父红，祖父一定黑，叔叔是祖父另一个孩子）

设：z 是当前冲突结点；p (z) 父；g (z) 祖父；u (z) 叔叔（父的兄弟）

#### Case1：叔叔是红色

> 
> 父红，叔叔红，祖父黑
> ✅处理：父亲变黑、叔叔变黑；祖父变红；然后把 z 跳到祖父位置继续向上循环。
> 本 case**只改颜色，不需要旋转**。问题向上传导。

#### Case2：叔叔黑色；z 是父结点的**右孩子**（LR 拐弯）

✅处理：先对父结点做一次左旋，转化为 case3。

#### Case3：叔叔黑色；z 是父结点的**左孩子**（直线）

✅处理：祖父右旋；原父结点变黑；原祖父变红；修复完成，循环结束。

> 
> ✨插入最多 2 次旋转就全部修复完毕！
> 循环结束最后强制把根置黑色。

> 
> 记忆口诀：叔红就变色上推；叔黑先转成直线再旋转改色收尾。

## 五、删除（难点！）

> 
> BST 删除本身就复杂；红黑树删除之后，最大麻烦是**丢失一个黑色结点，黑高被破坏**。
> 概念：**双重黑色**：删除之后某个结点临时背负 “多一份黑色”，记为额外黑，只是逻辑状态，结点本身颜色不变。双重黑就是本路径少掉一个黑色，需要向上消解这个额外黑色。

删除整体流程：

1. BST 标准删除（找后继替换）；记下被实际移除结点的颜色。
2. 如果被删掉结点是红色：万事大吉！红结点删掉不会改动黑高，直接结束。
3. 如果被删掉结点是**黑色**：产生双重黑色结点，向上进入删除修复循环，消解双重黑。

删除修复一共 4 个 case（x 代表双重黑结点）

- Case1：x 的兄弟是红色
→旋转，重新染色，转入 case2/3/4
- Case2：x 兄弟是黑，兄弟两个孩子也都是黑
→兄弟变红；把双重黑向上扔给父结点，继续循环向上
- Case3：x 兄弟黑；兄弟左红，右黑
→先右旋 + 改色，转为 case4
- Case4：x 兄弟黑；兄弟右孩子红
→一次旋转 + 重新染色，直接全部消除双重黑，结束修复

> 
> 删除最多**3 次旋转**。插入最多 2 次旋转。
> 大部分修复依然只是改颜色，旋转次数很少，这就是红黑树性能优势来源。

## 六、红黑树 vs AVL 回顾（核心对比）

表格

| 项目     | 红黑树                                            | AVL 树                       |         |                  |
| -------- | ------------------------------------------------- | ---------------------------- | ------- | ---------------- |
| 平衡约束 | 黑高相等；禁止红红；最长路径≤2 倍最短             | 平衡因子                     | h_l‑h_r | ≤ 1 严格高度约束 |
| 树高     | \(h \le 2\log n\)                                 | \(h \approx 1.44\log n\)     |         |                  |
| 查找     | 略慢                                              | 略快                         |         |                  |
| 增删修复 | 优先变色；旋转很少；插入最多 2，删除最多 3 次旋转 | 每次失衡就旋转；旋转次数更多 |         |                  |
| 适用场景 | 频繁插入删除；内核，std::map                      | 读多写少场景                 |         |                  |

> 
> 为什么 C++ std::map、Linux 内核选红黑树？
> 动态集合经常增删；旋转修改指针开销高于内存改颜色；红黑树减少旋转次数，综合吞吐更好；牺牲一点点查找速度换取修改性能。

## 七、面试高频坑点总结

1. ❌误区：红黑树是高度差≤2。
✅错！**不是高度差，是最长路径≤2 倍最短路径。高度差可以大于 2。约束来自黑高性质，不是直接高度。**
2. ❌误区：新插入结点选黑色。
✅错！新结点必须红色，否则直接破坏黑高。
3. ❌误区：红黑树没有平衡因子。
✅对！红黑树不维护平衡因子；靠颜色规则维护平衡。
4. 删除麻烦根源：删掉黑色结点会破坏黑高，引入双重黑的逻辑概念。
5. NIL 哨兵结点是黑色，所有叶子都是 NIL，不是普通数据结点。

## 八、拓展

B‑树（B + 树）是多路平衡；红黑树是二叉；B + 树用于磁盘数据库索引；红黑树用于内存内有序集合。
