# 端侧大模型手机、本地大模型 PC 完整技术栈

> 
> 端侧大模型核心矛盾：**大模型高算力 / 大内存需求 ↔ 手机 / PC 内存、功耗、散热受限**；整套技术分为：**硬件层、模型轻量化压缩、Transformer 架构改造、KV‑Cache 内存优化、推理引擎与算子优化、系统调度、软硬协同**七大模块。
> 手机端侧重**NPU、功耗约束、内存紧张**；PC 本地大模型侧重**CPU/GPU/NPU 异构，更大内存，可承载更大参数量**。

## 一、硬件层（算力底座）

### 📱端侧 AI 手机

1. **NPU 神经网络加速器（Hexagon / 神经网络引擎 / 自研 NPU）**
专用硬件矩阵运算单元，Transformer 矩阵乘法、量化运算硬件加速；旗舰手机 NPU 算力 20‑45TOPS，功耗严格受控（2‑5W），不能长时间满跑，会降频温控。
2. CPU：ARM 大核，负责调度、解码、采样、NPU 无法接管的算子。
3. LPDDR 内存：**内存是真正瓶颈**，7B 模型 INT4 需要约 3.5‑4GB 内存，手机可用内存有限，模型不能常驻内存，需要动态加载 / 卸载。
4. 存储：UFS，存放量化后的模型权重文件。

### 💻本地大模型 PC（Windows/macOS）

1. **PC NPU**：Intel Lunar Lake NPU、AMD Ryzen AI NPU、Apple Neural Engine (M 系列)，负责低功耗推理。
2. **集成 / 独立 GPU**：NVIDIA RTX、AMD 独显，CUDA / Metal 后端，是 PC 本地大模型主力算力，显存承担模型权重、KV‑Cache。
3. X86‑64 CPU，AVX2/AVX‑512 指令集，CPU 纯推理方案。
4. 大容量 DDR 内存，游戏本 / 台式机可以跑 7B‑13B 甚至更大量化模型。

> 
> 差异：手机高度依赖 NPU + 严格功耗温控；PC 可以 GPU 跑满，散热条件更好，支持更大参数量。

## 二、模型轻量化压缩技术（把大模型变小，端侧部署前提）

1. **模型量化（最重要）**
把 FP16/BF16 权重压缩到**INT8 / INT4 / FP4 / 2‑bit**；

- W4A8：权重 4bit，激活值 8bit，兼顾体积与精度，手机端主流；
- AWQ、GPTQ：权重感知量化，降低低比特下精度损失，PC 端大量使用；
- GGUF 格式（llama.cpp）广泛用于手机、PC 本地模型分发，支持多档位量化 Q4_K_M/Q5_K_M 等。

> 
> 效果：7B FP16=14GB；INT4 量化≈3.5‑4GB，体积压缩 4 倍以上。

2. **知识蒸馏**
用云端大模型 (教师) 输出训练小参数量学生模型（1B‑7B），端侧原生小模型：MiniCPM、Phi‑3、Qwen2.5‑3B/7B、Llama3.2 系列，专门面向端侧优化。
3. **剪枝 & 稀疏化**
剔除模型冗余权重，结构化稀疏，减少计算量；手机端落地相对少，PC 开源框架使用较多。
4. **MoE 稀疏模型**
每次推理只激活部分专家，同等效果下降低单次推理算力；但全部权重仍然占用存储，手机端落地有限，PC 本地可以使用。

## 三、Transformer 架构改造（原生模型适配端侧）

1. **GQA 分组查询注意力**
减少 KV 头数量，大幅降低 KV‑Cache 体积；Llama‑3、Qwen2.5 等端侧模型原生采用。

> 
> MHA→GQA，KV‑Cache 可降到原来 1/4，精度损失很小。

2. MLA 多头潜在注意力：进一步压缩 KV‑Cache，DeepSeek 系列使用。
3. 限制上下文窗口：手机端通常 4k‑8k 上下文，PC 本地可以支持 32k/128k。

## 四、KV‑Cache 专项优化（端侧内存最大开销）

> 
> KV‑Cache 存储历史对话 token，长对话场景内存占用甚至超过模型权重本身，是端侧头号瓶颈。

1. **KV‑Cache 量化**：把 KV 缓存本身也做 INT4/FP8 压缩，内存直接减半。
2. **PagedAttention 分页注意力**：借鉴操作系统虚拟内存，KV 缓存按页分配，消除内存碎片，vLLM、MLC‑LLM、移动端框架均移植该思想。
3. KV 缓存重计算、滑动窗口、KV‑Cache 剪枝：丢弃久远 token，控制内存上限，手机端必用。
4. Prefill/Decode 两阶段差异化调度：
   - Prefill：输入 prompt，计算密集；
   - Decode：逐 token 输出，**内存带宽瓶颈**；端侧两套路径分开优化。

## 五、推理引擎 & 算子优化（软件核心）

### 主流推理框架

- **llama.cpp**：C/C++ 跨平台事实标准，支持 CPU/NPU/CUDA/Metal/Vulkan，GGUF 权重，手机、PC 都大量使用。
- ExecuTorch (Meta)：移动端极小运行时，适配安卓、iOS NPU。
- MNN：阿里开源，ARM 手机端深度优化。
- ONNX Runtime Mobile：厂商系统内置 AI 运行时。
- PC 端：Ollama、LMStudio 底层基于 llama.cpp；Windows DirectML、Apple Foundation Models 框架。

### 关键算子优化技术

1. **算子融合 Operator Fusion**：把多个小算子合并成一个大算子；减少 NPU/GPU 内核调用、减少中间张量内存读写，速度提升 15‑25%，端侧收益极高。
2. **硬件原生低比特矩阵乘法**：针对 NPU/NVIDIA CUDA/Metal 手写 INT4 矩阵乘内核。
3. **内存映射 mmap**：模型权重不一次性全部载入内存，按需从磁盘读取，解决手机内存不足，大模型在有限 RAM 设备运行。
4. 投机采样 (Speculative Decoding)：小模型预生成 token，大模型校验，推理速度提升 1.3‑2.5 倍，手机 PC 都在采用。
5. 内存池、张量复用，避免频繁动态内存分配。

## 六、异构调度与系统层技术

1. **异构计算任务卸载**
计算密集矩阵运算交给 NPU/GPU；逻辑控制、采样、分词交给 CPU；框架自动做算力调度。

> 
> 手机 NPU 不是万能：部分算子 NPU 不支持，会回退到 CPU，造成性能跳水。

2. 内存管理：模型权重、KV‑Cache、系统内存之间动态抢占；手机后台自动卸载模型释放内存。
3. 温控保护：手机 NPU 高负载会发热，到达阈值自动降算力、降生成速度。
4. 模型分发：增量下载、按需下发不同量化版本，手机不预装完整大模型，按需下载权重文件。

## 七、手机端侧大模型 vs PC 本地大模型技术差异简表

表格

| 维度           | AI 手机端侧大模型                 | 本地大模型 PC                    |
| -------------- | --------------------------------- | -------------------------------- |
| 主要算力       | NPU 为主，CPU 辅助                | GPU 为主，NPU/CPU 为辅           |
| 典型可跑参数量 | 1‑7B（4bit 量化）                 | 7‑27B（4bit），高配可上 70B 量化 |
| 核心约束       | 内存紧张、功耗、发热温控          | 内存 / 显存，功耗约束宽松        |
| KV‑Cache 策略  | 强制滑动窗口、剪枝、分页          | 可支持超长上下文 KV 缓存         |
| 推理框架       | ExecuTorch、MNN、厂商自研 NPU SDK | llama.cpp+CUDA/Metal、Ollama     |
| 典型使用模式   | 系统常驻，按需唤醒，后台可卸载    | 可长时间驻留内存，持续推理       |

## 八、现实约束（产品层面）

1. 同样 7B 模型，手机上只能跑 4bit 及以下，PC 可以跑更高精度版本。
2. 手机 NPU 存在算子兼容性坑，部分算子只能回退 CPU，实际体验低于纸面 TOPS 算力。
3. **内存墙大于算力墙**：能不能跑，优先看可用内存，其次看芯片算力。
