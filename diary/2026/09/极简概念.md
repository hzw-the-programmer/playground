# RTL / Verilog / UVM / 形式化验证 极简概念

## 1. Verilog & RTL

**RTL（Register Transfer Level，寄存器传输级）**
是芯片硬件的抽象描述层级，介于高层架构和底层晶体管之间。它描述：数据在寄存器之间如何流动、运算、跳转，**不是写软件程序，是描述硬件电路本身**。

**Verilog**：最主流的硬件描述语言，用来写 RTL 代码。

- C/Python：**指令，CPU 去执行**；
- Verilog：**描述电路长什么样，综合工具把代码翻译成门电路、触发器**。

```verilog
// 极简Verilog示例：2输入与门
module and_gate(
    input a, b,
    output reg c
);
always @(*) begin
    c = a & b;
end
endmodule
```

> 
> 软件是 “运行”；Verilog 是 “被综合成硬件”，同一时刻多条逻辑**并行执行**，这和普通软件串行思维完全不同。

## 2. RTL 仿真

把 Verilog 喂给仿真器（Verilator、VCS），给输入激励，看输出是否符合预期。

- 仿真：在电脑上模拟芯片行为，**没有制造芯片，纯软件模拟电路**；
- 仿真能发现大部分逻辑错误，但无法反映真实芯片的时序、电压、工艺缺陷。

## 3. UVM（Universal Verification Methodology）通用验证方法学

写 RTL 只是第一步，芯片最大工作量是**验证**，保证硬件逻辑不出 bug。
UVM 是一套工业级标准验证框架，用 SystemVerilog 搭建验证环境：

- 生成海量随机测试激励；
- 驱动信号输入 DUT (待测 RTL 模块)；
- 采集输出，对比参考模型判断对错；
- 统计功能覆盖率：哪些电路分支、场景被测到。

传统项目：硬件工程师写 RTL，验证团队手写 UVM 测试用例，往往占项目一半人力。

> 
> Redwood 的突破点之一：**AI 自动生成 UVM 验证环境、测试用例、断言**，不用人手动编写。

## 4. SVA（SystemVerilog Assertion）断言

在代码里嵌入逻辑断言：“某条件必须成立”。
例：当 DMA 发起读请求，若干周期后必须返回有效数据。
仿真运行时一旦违反断言，立刻报错定位 bug。

## 5. 形式化验证 Formal Verification

和仿真完全不同的验证思路：

- 仿真：跑有限个测试用例，只能测一部分场景，**测过不代表没有 bug**；
- 形式化验证：数学符号遍历全部合法输入空间，**数学上证明某条属性永远成立**。

> 
> 能力：可以证明 “在所有可能输入下，该硬件不会出现死锁、不会越权访问、握手协议不会出错”。
> 局限：规模不能无限大，完整大芯片无法全盘形式化，一般用于关键模块。

Redwood 流程：

> 
> AI 生成 RTL → AI 生成 SVA 断言 + UVM 环境 → 仿真跑大量用例 + 形式验证做关键属性证明 → 收集覆盖率；
> 报错信息回传给 LLM，自动修改 RTL，循环迭代，直到验证指标达标。

## 串联整个流程，帮助理解 Redwood

1. 人类输出文档：我需要一个 Transformer 推理加速器，支持 Qwen‑7B，目标能效优先；
2. Agent 搜索硬件参数（阵列、SRAM、DMA、片上网络）；
3. AI 输出 Verilog RTL 硬件；同时输出固件、算子；
4. AI 自动产出 UVM 测试套件 + SVA 断言；
5. 调用仿真器、形式验证引擎，发现逻辑 bug；
6. 错误日志返回给大模型，修改 RTL，反复迭代；
7. 验证通过后，综合生成网表，编译输出 FPGA 比特流；
8. 烧录 FPGA 板子，真实跑大模型推理。

> 
> 注意：上面全部属于**芯片前端设计**；
> 后端：布局布线、时序收敛、PDK 工艺库、版图、流片制造，这套 AI 系统目前不处理。
