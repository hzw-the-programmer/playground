# 结构化表达

**定义**：先总后分、框架先行、分层有序地输出观点，把零散信息整理成清晰逻辑，让听众 / 读者快速抓住重点，核心三要素：**结论先行、分层分类、逻辑递进**。

## ✅ 核心原则（金字塔原理）

1. **结论先行**：先说最终观点 / 结果，不要铺垫半天再讲重点
❌ 昨天堵车、客户临时改需求，最后项目延期了
✅ 本次项目延期，主要有两个原因：①交通延误 ②客户临时调整需求
2. **以上统下**：上层是结论，下层是支撑结论的论据，上下对应
3. **归类分组**：同类信息放一起，避免杂乱（MECE：相互独立、完全穷尽）
4. **逻辑递进**：分组内容按顺序排列：时间｜空间｜重要性｜因果

## 📌 3 种常用基础框架

### 1. PREP（汇报、沟通、演讲，最通用）

- P Point 结论：核心观点
- R Reason 理由：支撑依据
- E Example 案例 / 数据：具象佐证
- P Point 重申结论：收尾强化

> 
> 示例：
> P：建议优先上线会员功能
> R：可以提升复购、拉高用户留存
> E：竞品上线后留存提升 20%
> P：因此建议本季度启动会员版本开发

### 2. SCQA（写方案、开场、问题分析）

- S Situation 背景：现状是什么
- C Complication 冲突：存在什么问题
- Q Question 疑问：核心要解决什么
- A Answer 答案：给出方案

### 3. 三点式（日常简短沟通，大脑最容易记忆）

任何问题尽量归纳为 **3 个维度** 展开，不要罗列一堆零散条目
例：本次优化从 流程、人员、工具 三方面推进

## 🧩 常见逻辑排序方式

1. **时间顺序**：过去→现在→未来；事前→事中→事后
2. **重要性顺序**：最重要→次要→补充（职场汇报首选）
3. **结构顺序**：整体拆分模块（公司部门、产品功能）
4. **演绎顺序**：大前提→小前提→结论

## ❌ 结构化表达避坑

1. 不要想到哪说到哪，堆砌信息
2. 分层不要交叉重复（MECE，论据互不重叠）
3. 层级不宜过多：建议不超过 **3 层**，每层 3 点最优
4. 区分 “观点” 和 “事实 / 数据”，论据不能全是主观感受

## 🛠 落地练习模板（直接套用）

> 
> 总：我的结论是____
> 分 1：理由一（案例 / 数据：****）
> 分 2：理由二（案例 / 数据：****）
> 分 3：理由三（案例 / 数据：****）
> 总：综上，****

## 🎯 适用场景

工作汇报、会议发言、面试回答、写方案、写周报、口头沟通、短视频文案
