# Rust 生命周期（Lifetime）

**生命周期本质：描述引用的有效存活时间范围，告诉编译器这个引用能活多久，用来防止悬垂引用。**

> 
> 关键点：
> 
> 
> 1. 生命周期**不会改变对象实际存活时长**，只是给编译器做校验的标记，运行时几乎没有开销。
> 2. 生命周期不是对象的寿命，是**引用的寿命**。
> 3. 绝大多数情况编译器可以自动推导（生命周期省略规则），只有歧义的时候才需要手动标注 `'a`。

## 1. 为什么需要生命周期？问题来源：悬垂引用

```rust
fn bad() -> &String {
    let s = String::from("hello");
    &s
}
```

函数结束，`s` 被 `drop` 销毁，返回的引用指向已经销毁的内存。C/C++ 编译通过运行时崩溃；**Rust 直接编译报错**。

编译器要判断：**这个引用指向的数据什么时候还活着？引用不能超过数据的寿命**，生命周期就是干这件事。

## 2. 生命周期语法

生命周期以单引号开头，一般用短名字：`'a`、`'b`、`'ctx`。

### 函数上标注生命周期

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

`'a` 的含义：

> 
> 返回值引用的生命周期，**不能超过 x 和 y 中较短的那一个生命周期**。

并不是说 x、y 必须活一样久；而是返回出来的引用，存活范围被约束为两者交集。

调用示例：

```rust
fn main() {
    let s1 = String::from("abcd");
    {
        let s2 = String::from("xyz");
        let res = longest(s1.as_str(), s2.as_str());
        println!("{}", res); // res 生命周期受限于 s2，只能在这个块内使用
    }
    // println!("{}", res); // res 已经失效，编译报错
}
```

> 
> ❗重要理解：生命周期参数 `'a` 是**约束关系**，不是强制把变量生命拉长。不能延长任何对象寿命。

## 3. 生命周期省略规则（隐式生命周期）

早期 Rust 必须到处写 `'a`；后来引入三条省略规则，很多函数不用手写生命周期。

> 
> 规则只针对函数参数、返回的引用：

1. **每一个输入引用参数，分配一个独立生命周期**
2. 如果只有**一个输入生命周期参数**，把该生命周期分配给所有输出引用。
3. 如果是方法（`&self` / `&mut self`），把 `self` 的生命周期分配给输出引用。

示例，下面两段等价：

```rust
// 省略版
fn first(s: &str) -> &str {
    &s[0..1]
}

// 展开完整版
fn first<'a>(s: &'a str) -> &'a str {
    &s[0..1]
}
```

当编译器无法应用三条规则，就强制要求你手动写生命周期，典型就是上面的 `longest`，两个输入引用，无法判断返回值跟随哪一个，必须显式 `'a`。

## 4. 结构体中的生命周期

结构体持有引用，**必须标注生命周期**，告诉编译器结构体实例不能活得比引用的数据久。

```rust
// 结构体不能比引用的字符串活得久
struct Excerpt<'a> {
    part: &'a str,
}

fn main() {
    let text = String::from("hello world");
    let e = Excerpt { part: &text[0..5] };
    println!("{}", e.part);
}
```

`Excerpt<'a>`：`Excerpt` 实例里面的 `part` 引用，生命周期不能超过 `'a`。

> 
> 如果结构体存的是所有权类型 `String`（不是引用），**完全不需要生命周期**。

## 5. 方法 impl 块上的生命周期

```rust
impl<'a> Excerpt<'a> {
    fn get_part(&self) -> &str {
        self.part
    }
}
```

- `impl<'a>`：声明生命周期参数
- `&self` 是 `&'a self`，根据省略规则，返回 `&str` 自动获得 `'a`。

## 6. 特殊生命周期

### `'static`

代表**整个程序运行期都有效**。两种来源：

1. 字符串字面量：`let s: &'static str = "hello";`，编译二进制内置，程序全程存在。
2. `Box::leak` 泄漏出来的引用。

> 
> ⚠️ 不要随便给变量加上 `'static`，不能把局部变量强行变成 static。

```rust
fn demo() {
    let x = String::new();
    let r: &'static str = &x; // 编译报错，x 局部，不可能 static
}
```

## 7. 常见误区澄清

1. ❌ “`'a` 让变量活得更长”
✅ 生命周期只是约束检查，**不能改变对象实际存活时间**，对象什么时候销毁由所有权和作用域决定。
2. ❌ 生命周期是运行时概念
✅ 生命周期完全编译期检查；运行时不存在 `'a` 标记，无性能损耗。
3. ❌ 所有函数都要写生命周期
✅ 大部分场景靠**生命周期省略规则**自动推导；只有返回引用且编译器无法确定来源时，才要手写。
4. ❌ 生命周期 = 对象作用域
✅ 生命周期描述**引用**的有效区间；对象的销毁由所有权 `drop` 决定。

## 8. 生命周期和所有权的关系

- **所有权**：决定数据什么时候被释放（drop）。
- **生命周期**：约束引用，保证引用不能访问已经被 drop 的数据。

所有权决定 “什么时候死”；生命周期规则保证 “你不能拿着引用去访问已经死掉的数据”。两者配合杜绝悬垂引用。

## 极简总结

1. 生命周期 `'a` 是给编译器看的标记，描述**引用的有效范围**，防止悬垂引用。
2. 不能延长对象寿命，只做约束校验。
3. 函数多引用参数返回引用，结构体存引用，需要显式标注。
4. 三条省略规则让大多数代码不用手写生命周期。
5. `'static` 代表引用存活整个程序生命周期。
