# Unix 核心设计理念

Unix 的设计思想最早来自贝尔实验室的 Ken Thompson、Dennis Ritchie，后续由 Doug McIlroy 等人总结提炼，是现代 Linux、macOS 的思想源头，分为**核心哲学原则**与**系统设计特征**两部分。

## 经典 Unix 哲学（Doug McIlroy）

1. **小即是美**
每个程序只做好一件事，功能单一、聚焦，不做大而全。不要把一堆逻辑塞进同一个程序；复杂能力靠组合而非单体实现。
2. **让程序只做一件事，并把它做好**
工具职责边界清晰。比如 `ls` 只列目录，`grep` 只做文本匹配，`sort` 只排序，不互相越界。
3. **允许程序组合复用**
提供管道 `|`，把一个程序的输出直接作为另一个程序的输入。通过简单工具拼接，完成复杂任务，不需要重写大程序。
4. **使用文本作为通用接口**
一切交互优先用**纯文本流**。文本简单、通用，人可读，也方便各类程序解析；避免二进制私有格式，降低耦合。
5. **尽量避免交互式用户界面**
程序优先支持非交互、脚本化运行；方便被脚本调用、自动化批处理。交互只是附加，不是主体。
6. **把软件配置存放在文本文件**
配置为普通可读文本，不是数据库或神秘二进制，方便编辑、版本管理、工具批量处理。

## 系统层面核心设计

### 1. 一切皆文件（Everything is a file）

普通文件、目录、硬件设备、管道、socket，全部抽象为**文件描述符**。
读写设备和读写普通文件用同一套 open/read/write/close 系统调用，极大简化接口。

> 
> 目录是特殊文件；设备放在 `/dev`；管道、socket 也走文件描述符语义。

### 2. 分层、模块化内核

- 内核负责：进程调度、内存管理、文件系统、设备驱动、系统调用。
- 应用跑在用户态，通过**系统调用**陷入内核，用户程序不直接操作硬件。
- 内核空间 / 用户空间严格隔离，保障稳定性。

### 3. 进程模型：fork‑exec 模型

- `fork()`：复制现有进程生成子进程；
- `exec()`：在子进程里加载替换成新程序。
创建进程的这套机制是 Unix 的标志性设计；shell、服务、工具全部基于该模型。

### 4. 树状文件系统

单一根目录 `/`，设备挂载到目录树任意节点，没有 Windows 多个盘符概念。

### 5. 简单统一的权限模型

用户、用户组，读 / 写 / 执行 rwx 权限位，对文件、目录生效。

## 补充引申原则（后来社区总结）

- **沉默是金**：程序若无错误就尽量少输出，不要打印一堆无关信息；便于管道处理。
- **可移植优先**：用 C 语言重写，摆脱硬件绑定，这是 Unix 能广泛传播的关键。
- **宁可复杂在工具，不复杂在内核**：内核保持精简，复杂逻辑放到用户态工具。

## 反例对比

很多现代系统会违背部分 Unix 哲学：大单体软件、二进制配置、重度 GUI、私有二进制协议；而 Linux 很大程度继承这套理念。
