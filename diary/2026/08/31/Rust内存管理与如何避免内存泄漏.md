# Rust 内存管理与如何避免内存泄漏

Rust 核心靠**所有权（Ownership）、借用（Borrowing）、生命周期（Lifetime）**这套编译期规则管理内存，**绝大多数内存错误在编译阶段拦截**，不需要 GC，也不需要手动 malloc/free。

> 
> 注意：Rust 不是完全杜绝内存泄漏，只是**普通野指针、悬垂引用、双重释放被编译器消灭；逻辑层面泄漏依然可以发生**。

## 一、核心内存机制

### 1. 所有权 Ownership

每条数据**有且仅有一个所有者**：

1. 值离开作用域（`}`）时，自动调用 `drop`，释放内存。
2. 赋值、传参默认是**移动语义 (move)**，转移所有权，原变量失效。

```rust
fn demo() {
    let s = String::from("hello"); // s 是所有者
    take(s);                       // 所有权移动到函数内
    // println!("{}", s); // 编译报错！s 已经不再拥有数据
}

fn take(_x: String) {
} // _x 作用域结束，drop，内存释放
```

栈上类型（i32、bool、f64）实现 `Copy` trait，是复制而非移动。

### 2. 借用 & 引用 Borrowing

不想转移所有权，使用引用 `&T`（不可变借用）、`&mut T`（可变借用）：

> 
> 借用规则（编译期检查）

1. 同一时间：**可以多个不可变引用，或最多一个可变引用，二者不能共存**
2. **引用不能活得比被引用的数据久**（悬垂引用编译报错）

```rust
fn no_dangle() -> &String {
    let s = String::from("hi");
    &s // 编译报错：s 函数结束就销毁，不能返回内部引用
}
```

### 3. 生命周期 Lifetime `'a`

标注引用存活范围，告诉编译器引用有效区间，解决函数返回引用的校验。
大部分场景编译器可以**生命周期省略**，复杂场景手动标注。

## 二、Rust 会消灭哪些内存问题

✅ 悬垂引用 (dangling reference) → 编译错误
✅ 双重释放 (double free) → 所有权唯一保证
✅ 使用已释放内存 → 编译拦截
✅ 迭代器失效 → 借用检查拦截

> 
> ❗**Rust 依然可以内存泄漏**
> 所有权系统防不了**逻辑泄漏**：

1. `Rc<T>` / `Arc<T>` 循环引用，引用计数永远不为 0，内存永远不释放
2. 把数据泄露到全局（`Box::leak`）有意泄漏
3. IO、线程阻塞，堆数据持续持有无法释放

### 示例：Rc 循环引用造成内存泄漏

```rust
use std::rc::{Rc, Weak};
use std::cell::RefCell;

#[derive(Debug)]
struct Node {
    next: Option<Rc<RefCell<Node>>>,
}

fn main() {
    let a = Rc::new(RefCell::new(Node{next: None}));
    let b = Rc::new(RefCell::new(Node{next: Some(a.clone())}));
    a.borrow_mut().next = Some(b.clone());
    // a、b 互相引用，Rc 计数永远 ≥1，退出作用域内存不会释放 → 内存泄漏
}
```

**修复：把其中一个改为 `Weak<T>` 弱引用，不增加强计数，打破循环。**

## 三、各类智能指针用途（内存管理组件）

表格

| 指针         | 作用                       | 所有权       | 是否计数     | 风险点                   |
| ------------ | -------------------------- | ------------ | ------------ | ------------------------ |
| `Box<T>`     | 堆分配，独占所有权         | 独占         | 无           | 普通，离开作用域释放     |
| `Rc<T>`      | 单线程共享所有权           | 共享         | 引用计数     | 循环引用泄漏             |
| `Arc<T>`     | 多线程共享所有权           | 共享         | 原子引用计数 | 循环引用泄漏             |
| `RefCell<T>` | 内部可变性，运行时借用检查 | 独占         | 无           | 运行时 panic，不能跨线程 |
| `Weak<T>`    | 弱引用，配合 Rc/Arc        | 不持有所有权 | 不增加强计数 | 可以 upgrade 失败        |

> 
> 原则：
> 
> 
> - 优先 `Box<T>`；共享再考虑 Rc/Arc；
> - 出现双向 / 环形关系，**必须用 Weak 切断循环，避免内存泄漏**。

## 四、实战：Rust 避免内存泄漏最佳实践

1. **尽量使用独占所有权 Box，少用 Rc/Arc**
共享引用计数是万不得已，优先重构数据结构，避免互相指向。
2. 双向图、树的父‑子关系：**子节点用 Weak 指向父节点**
子→父：`Weak<T>`；父→子：`Rc<T>`，杜绝循环引用。
3. 不要滥用 `Box::leak``Box::leak` 会永久泄漏内存，只用于静态生命周期特殊场景。
4. 检测内存泄漏工具

- `valgrind`：可以检测泄漏，但 Rust 很多正常 drop 场景 valgrind 噪音大
- `heaptrack`：Linux 下跟踪堆分配，看哪里堆内存只增不减
- 单元测试：`std::mem::size_of_val`，配合统计计数，定位泄漏路径

5. 线程场景注意：不要让长生命周期线程无限持有大对象，及时 drop；
如果把数据 move 进线程，线程结束数据自动释放；线程不退出则数据不会释放。

## 五、和 GC / C++ 的对比

1. C/C++：手动管理，所有错误都发生在运行时，野指针、double free、泄漏一大堆。
2. GC 语言 (Java/Go)：运行时扫描回收，牺牲运行时开销，不用关心所有权，但有 GC 停顿。
3. Rust：**编译期所有权检查，运行时无 GC 开销**；大部分内存错误编译挡掉；但**循环引用逻辑泄漏依然存在，需要开发者自己处理**。

## 简短总结

> 
> Rust 依靠**所有权 + 借用检查 + 生命周期**在编译期杜绝野指针、双重释放；堆数据离开作用域自动 drop。
> 唯一常见内存泄漏来源是 **Rc/Arc 循环引用**，使用 `Weak<T>` 弱引用打破循环即可。Rust 不能 100% 消除内存泄漏，但可以把绝大多数内存安全错误推到编译阶段。
